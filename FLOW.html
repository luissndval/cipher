Idea central
Cada comando deja rastro

Contexto, indices, packs, tareas, sesiones, auditoria y alertas quedan en disco.

1. clients/

Documentacion de contexto por cliente y repo. Archivos editables: ARCHITECTURE.md, BUSINESS_RULES.md, DEPENDENCIES.md, RISK_MATRIX.md.

2. .cipher/

Datos operativos: index/ (grafos), packs/ (contexto), tasks/ (tareas), sessions/, audit/, alerts/.

3. Flujo diario

Para desarrollar una tarea revisa packs/, tasks/ y sessions/. Para trazabilidad, audit/.

Flujo recomendado

El camino completo desde cero hasta ejecutar una tarea con agente.

1

Registrar y analizar

Usa cipheria init para escanear repos, elegir proveedor LLM y generar contexto inicial de negocio y arquitectura.

2

Indexar estructura

Usa cipheria index para extraer simbolos, imports y construir el grafo de dependencias. Sin LLM, puro parseo.

3

Crear task file

Crea un archivo feature-4040-mi-tarea.md con titulo y descripcion. El nombre define tipo, numero y rama automaticamente.

4

Ejecutar y auditar

Usa cipheria task feature-4040-mi-tarea.md para crear la tarea formal, analizar impacto y lanzar el agente.

Comandos — referencia completa

Cada bloque incluye uso, todos los flags, proceso interno paso a paso y archivos generados.

cipheria init

usa IA

Onboarding automatico: detecta repos Git, los registra bajo un cliente, elige proveedor LLM y genera contexto de negocio y arquitectura para cada repo.

cipheria init [--scan <ruta>]
FlagDescripcion
--scan <ruta>Directorio donde buscar repos .git (default: directorio actual)
  1. Escanea recursivamente buscando carpetas .git.
  2. Muestra repos encontrados y pide seleccion interactiva.
  3. Solicita nombre del cliente (default: nombre del directorio).
  4. Ofrece eleccion de proveedor: Gemini (contexto 400k) o Claude (contexto 60k).
  5. Por cada repo seleccionado: genera ARCHITECTURE.md, BUSINESS_RULES.md, DEPENDENCIES.md y RISK_MATRIX.md con IA.
  6. Crea index estructural inicial (simbolos e imports).
  7. Detecta dependencias cruzadas entre repos.
  8. Actualiza .cipher/config.json y agrega entradas a .gitignore.
clients/<cliente>/<repo>/ARCHITECTURE.md clients/<cliente>/<repo>/BUSINESS_RULES.md clients/<cliente>/<repo>/RISK_MATRIX.md .cipher/config.json

cipheria index

sin IA

Parseo estructural del codigo: extrae simbolos (funciones, clases, metodos), imports y construye el grafo de dependencias entre archivos.

cipheria index [--repo <ruta-o-nombre>]
FlagDescripcion
--repo <ruta>Ruta o nombre del repo a indexar (default: CWD)
  1. Detecta o recibe ruta del repo.
  2. Recorre todos los archivos fuente soportados (Python, JS, TS, Go, Java, etc.).
  3. Extrae por archivo: nombre, lenguaje, simbolos, imports, hash SHA-256.
  4. Usa ImportResolver para mapear imports a rutas reales de archivo.
  5. Construye grafo: nodos = archivos, aristas = importacion.
  6. Registra modulos externos (npm, pip, etc.) por separado.
  7. Guarda index.json y graph.json en disco.
  8. Muestra estadisticas: archivos, simbolos, imports, lenguajes, nodos, aristas.
.cipher/index/<repo>/index.json .cipher/index/<repo>/graph.json

Formato task.md

sin IA

En vez del prompt interactivo, crea un archivo .md con los datos de la tarea y pasalo directo a cipheria task.

cipheria task feature-4040-login-oauth.md

El nombre del archivo define tipo, numero y rama automaticamente:

Nombre de archivoTipoNumero
feature-4040-login-oauth.mdFEATURE4040
bug-123-fix-timeout.mdBUG123
hotfix-7-crash-mobile.mdHOTFIX7
task-99-refactor-auth.mdTASK99

Contenido del archivo (todo opcional salvo existir):

# Agregar autenticacion OAuth con Google Implementar flujo OAuth2 con Google como proveedor de identidad. Debe integrarse con el sistema de usuarios existente sin romper el login por email. Link: https://linear.app/acme/issue/ENG-4040
  1. El # Titulo (H1) se usa como titulo de la tarea. Si no hay H1, se genera del nombre del archivo.
  2. El cuerpo del archivo es la descripcion. Todo lo que no sea H1 ni Link:.
  3. La linea Link: <url> se guarda como source_ref en la tarea.
  4. La rama se genera automaticamente: feature-4040-agregar-autenticacion-oauth-con-google.

Algoritmo de scoring interno (context pack):

CriterioPuntosDescripcion
Keyword en ruta+2.0Por cada keyword de la tarea en el path del archivo
Keyword en simbolo+1.0Por cada keyword en nombres de funciones/clases
Alta demanda+0.5Archivo en top 20% de archivos mas importados
Tiene exports+0.3Archivo que exporta simbolos (no solo importa)
Nombre exacto+5.0Basename mencionado explicitamente en la tarea

cipheria task

pack + alert + agente

Comando principal de trabajo diario. Acepta descripcion libre, archivo .md, ticket de GitHub o Linear. Indexa repos, construye contexto, analiza impacto y lanza el agente.

cipheria task feature-4040-login.md cipheria task "<descripcion libre>" cipheria task --from-gh owner/repo#123 cipheria task --from-linear ENG-456 cipheria task --list [--status PENDING] cipheria task feature-4040.md --dry-run
Flag / ArgumentoDescripcion
feature-4040.mdLee la tarea desde un archivo markdown local
"descripcion"Texto libre (abre prompt interactivo si no se pasa nada)
--from-gh <owner/repo#N>Importa issue real desde GitHub (requiere gh CLI)
--from-linear <ID>Importa ticket real desde Linear API
--repo <nombre>Especifica el repo destino
--providerProveedor LLM: claude (150k) o gemini (400k)
--dry-runGenera intent y CIPHER_ALERT.md pero NO lanza el agente
--listLista todas las tareas registradas
--status <val>Filtra lista por PENDING, IN_PROGRESS, DONE, FAILED
  1. Resuelve la fuente de la tarea: archivo .md, texto libre, prompt interactivo, GitHub o Linear.
  2. Detecta el repo por CWD o muestra menu de seleccion interactivo.
  3. Indexa todos los repos del cliente de forma incremental (SHA-256 por archivo, solo re-parsea cambios).
  4. Construye y fusiona grafos de dependencia de todos los repos.
  5. Crea objeto Task con tipo detectado automaticamente, status PENDING.
  6. Construye context pack: scoring, seleccion de targets y dependencias, presupuesto de tokens.
  7. Genera ContextManifest con auditoria del contexto usado.
  8. Analiza impacto cross-repo con Gemini: escribe CIPHER_ALERT.md en la raiz del repo del cliente y lo agrega al .gitignore automaticamente.
  9. Genera TaskIntent: archivos a modificar, archivos a leer, restricciones detectadas.
  10. Lanza agente Claude inyectando contexto en CLAUDE.md temporal.
  11. Actualiza status de la tarea a DONE o FAILED. Loguea en audit_log.jsonl.

Ciclo de vida de una tarea:

PENDING → IN_PROGRESS → DONE / FAILED
<repo-cliente>/CIPHER_ALERT.md .cipher/tasks/<cliente>/<repo>/<task_id>/task.json .cipher/tasks/.../task_intent.json .cipher/packs/.../context_pack.md .cipher/alerts/<cliente>/alert-{TYPE}-{id}.md .cipher/audit/audit_log.jsonl

cipheria audit

lectura

Visualiza el historial append-only de sesiones de IA. Filtra, muestra estadisticas y permite registrar la URL del PR asociado a cada tarea.

cipheria audit [<task_id>] [--repo <n>] [--client <n>] [--since YYYY-MM] [--result done|failed|pending] [--pr <task_id> <url>] [--stats] [--limit N]
FlagDescripcion
<task_id>Muestra detalle completo de una tarea (posicional)
--repo <nombre>Filtra entradas por repo
--client <nombre>Filtra por cliente
--since YYYY-MMFiltra desde una fecha (e.g., 2024-03)
--result <val>Filtra por resultado: pending, done, failed
--pr <id> <url>Registra URL del PR para una tarea
--statsMuestra estadisticas globales (sesiones, tokens, por repo)
--limit NMaximo de entradas a mostrar (default 50)
  1. Lee .cipher/audit/audit_log.jsonl (append-only, nunca se sobreescribe).
  2. Aplica filtros combinables en memoria.
  3. En modo lista: muestra tabla con timestamp, task_id, repo, tokens, resultado.
  4. En modo detalle: carga el CONTEXT_MANIFEST.json completo del disco.
  5. En modo PR: actualiza el campo pr_url en manifest y log.
  6. En modo stats: agrega totales, por resultado y top repos.

cipheria impact

sin IA

Analiza que archivos se veerian afectados al modificar un archivo dado. Usa el grafo de dependencias para recorrido inverso por profundidad.

cipheria impact <archivo> [--repo <nombre>] [--depth N] cipheria impact # modo interactivo
FlagDescripcion
<archivo>Ruta relativa o sufijo del archivo a analizar
--repo <nombre>Repo a usar (auto-detectado desde CWD)
--depth NProfundidad maxima de recorrido (default: 10)
  1. Carga graph.json del repo.
  2. Resuelve el archivo destino (exacto, por sufijo o fuzzy match).
  3. Recorre el grafo de dependencias en sentido inverso hasta depth niveles.
  4. Agrupa resultados por profundidad (depth 1 = importadores directos, depth 2 = transitivos, etc.).
  5. Calcula nivel de riesgo segun cantidad de archivos afectados.
  6. Identifica archivos de test y config en el conjunto de impacto.

Niveles de riesgo por cantidad de archivos afectados:

Ninguno (0) Bajo (1-3) Medio (4-10) Alto (11-30) Critico (31+)

cipheria session

interactivo

Abre una sesion de desarrollo completa: ensambla contexto por capas, crea la descripcion de la tarea para el agente y lanza Claude Code.

cipheria session claude
  1. Detecta cliente y repo desde CWD o muestra menu de seleccion.
  2. Crea entrada en SessionStore con session_id y timestamp de inicio.
  3. Ensambla ACTIVE_CONTEXT.md combinando: CONVENTIONS.md (global) + BUSINESS_RULES.md (cliente) + ARCHITECTURE.md (repo).
  4. Abre prompt interactivo para: tipo de trabajo, numero de ticket, titulo, descripcion y link.
  5. Genera task-agent.md con instrucciones paso a paso para el agente, nombre de rama sugerido y checklist.
  6. Inyecta contexto en CLAUDE.md temporal antes de lanzar el agente.
  7. Al terminar: restaura o elimina CLAUDE.md, registra fin de sesion.
.cipher/sessions/<cliente>/<repo>/ACTIVE_CONTEXT.md .cipher/sessions/.../task-agent.md .cipher/sessions/.../session_<id>.json

cipheria status

lectura

Vista rapida del estado del repo actual: cliente registrado, archivos de contexto disponibles y su antigüedad.

cipheria status
  1. Lee .cipher/config.json y detecta el repo actual por git rev-parse.
  2. Muestra: nombre del repo, cliente, ruta y archivos de contexto con fecha de ultima modificacion.
  3. Lista todos los repos del mismo cliente.

Donde quedan los archivos generados

Si tu pregunta es "que reviso despues de correr un comando", esta es la seccion.

Todo parte desde la raiz del proyecto Carpetas principales: clients/ y .cipher/ Cada comando deja salidas distintas
Despues de cipheria init

Contexto por cliente y repo

clients/<cliente>/<repo>/
  • ARCHITECTURE.md — vision de arquitectura generada con IA
  • BUSINESS_RULES.md — reglas de negocio detectadas
  • DEPENDENCIES.md — dependencias externas y su proposito
  • RISK_MATRIX.md — matriz de riesgos del proyecto

Revisar primero: estos archivos son borrador de IA. Valida y edita segun corresponda.

Despues de cipheria index

Indices y grafo de dependencias

.cipher/index/<repo>/
  • index.json — archivos, lenguaje, simbolos (funciones/clases), imports, hash
  • graph.json — nodos (archivos), aristas (imports), modulos externos

Revisar si: queres entender la estructura real del codigo o diagnosticar impacto antes de cambiar algo.

Despues de cipheria pack

Pack de contexto para el agente

.cipher/packs/<repo>/<task_id>_<slug>/
  • context_pack.md — markdown con archivos seleccionados, reglas y arquitectura
  • context_manifest.json — metadata: archivos, roles (target/dependency), tokens usados, hash SHA-256

Revisar primero: si queres ver exactamente que contexto recibe el agente antes de ejecutar.

Despues de cipheria task

Tarea formal e intent

.cipher/tasks/<cliente>/<repo>/<task_id>/
  • task.json — tipo, titulo, descripcion, repo, status, fuente (manual/gh/linear), timestamps
  • task_intent.json — archivos a modificar, archivos a leer, restricciones detectadas

Revisar si: queres confirmar objetivo, alcance, archivos involucrados y restricciones antes de que el agente actue.

Despues de cipheria task o cipheria session

Manifest y contexto de sesion

.cipher/sessions/<cliente>/<repo>/<task_id>/
  • CONTEXT_MANIFEST.json — evidencia de que archivos vio el agente
  • ACTIVE_CONTEXT.md — contexto ensamblado por capas (global + cliente + repo)
  • task-agent.md — instrucciones generadas para el agente

Revisar si: queres auditar exactamente que informacion tuvo disponible el agente en una ejecucion.

Despues de cipheria task — analisis de riesgo

Alertas de impacto cross-repo

.cipher/alerts/<task_id>/
  • ALERT.md — archivos afectados por profundidad, tests en riesgo, configs impactadas
.cipher/audit/audit_log.jsonl
  • Log append-only con todas las sesiones: timestamp, tokens, resultado, hash de contexto.

Revisar si: queres trazabilidad completa, estadisticas de uso o detectar impacto entre repos.

Que deberias revisar segun tu objetivo

En vez de abrir todo, revisa solo la carpeta que corresponde al tipo de validacion que queres hacer.

Quiero validar contexto de negocio

Abri clients/

La mejor carpeta para revisar si la documentacion generada tiene sentido funcional y arquitectonico. Editable directamente.

  • ARCHITECTURE.md
  • BUSINESS_RULES.md
  • DEPENDENCIES.md
Quiero entender dependencias reales

Abri .cipher/index/

Datos estructurales del codigo, no interpretaciones. La fuente mas confiable para analisis de impacto tecnico.

  • index.json — simbolos e imports por archivo
  • graph.json — grafo de dependencias
Quiero ver que le pasaron al agente

Abri .cipher/packs/ y .cipher/sessions/

Si necesitas verificar el contexto exacto usado en una tarea, estas dos carpetas son las correctas.

  • context_pack.md
  • CONTEXT_MANIFEST.json
  • ACTIVE_CONTEXT.md
Quiero saber que tarea se creo

Abri .cipher/tasks/

Muestra la tarea formal, el tipo detectado, el intent y el status actual.

  • task.json — metadata de la tarea
  • task_intent.json — que archivos tocar y restricciones

Capas del proyecto

El contexto que recibe el agente se ensambla combinando tres fuentes en orden fijo. Cada capa agrega especificidad.

Capa Global + Capa Cliente + Capa Proyecto → ACTIVE_CONTEXT.md
Capa 1 — Global

Reglas de la consultora

Convenciones universales de codigo que aplican a todos los proyectos y clientes. Se leen desde global/.

CONVENTIONS.md WORKFLOW.md AGENT.md
Capa 2 — Cliente

Contexto del cliente

Reglas de negocio compartidas entre todos los repos del mismo cliente. Se leen desde clients/<cliente>/.

BUSINESS_RULES.md ARCHITECTURE.md
Capa 3 — Proyecto

Contexto del repo

Arquitectura, dependencias y riesgos especificos del repo activo. Se leen desde clients/<cliente>/<repo>/.

BUSINESS_RULES.md ARCHITECTURE.md DEPENDENCIES.md RISK_MATRIX.md
Salida ensamblada

ACTIVE_CONTEXT.md

Markdown final generado por cipheria session. Combina las 3 capas y se inyecta al agente antes de lanzarlo.

.cipher/sessions/<cliente>/<repo>/ACTIVE_CONTEXT.md
Modo summary: por defecto cada archivo se trunca a 30 lineas (o usa un .summary.md si existe) para no exceder el budget de tokens del agente.

Mapa mental rapido

Resumen para recordar donde buscar sin pensar demasiado.

clients/ = contexto humano

Documentacion editable y revisable. La genera la IA pero la valida la persona.

.cipher/index/ = estructura tecnica

Simbolos, imports y dependencias reales extraidos del codigo. Sin interpretacion.

.cipher/packs/ = contexto minimo

Los archivos seleccionados y el presupuesto de tokens para una tarea concreta.

.cipher/tasks/ = definicion de trabajo

Objetivo, tipo detectado, intent y archivos a considerar para el agente.

.cipher/sessions/ = evidencia de ejecucion

Manifest, contexto activo y task-agent.md de cada sesion de agente.

.cipher/audit/ = historial append-only

Log de trazabilidad, tokens usados y base para PR comments y estadisticas.

Regla practica: si queres revisar documentacion, entra a clients/. Si queres revisar datos generados por el sistema, entra a .cipher/.
